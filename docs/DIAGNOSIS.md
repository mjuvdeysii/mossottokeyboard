# 诊断：为什么真机上还是不如普通输入法「灵活」（2026-11-03）

> 问题（产品负责人，真机测试）：比之前好很多，但仍不如普通输入法灵活；怀疑是常用句子库、词库的问题。
> 本文只记录**实测**与**推断**，两者分开写。所有数字都在本机 `-O`、带句子模型（`sentence.gram`）、
> 305 句调参集上取得。

## 一、事实：24 个错例是什么形状

`PERFECT_DEBUG=1 ... bench` 列出全部失败句。24 句里：

| 类别 | 例 | 条数 |
|---|---|---|
| 的 / 得 | 标题写的太长了、最近睡的不太好 | 2 |
| 他 / 她 | 他会自己穿鞋了、她最喜欢小兔子、他是我的大学同学 | 3 |
| 其它同音词 | 收货/收获、离/里、再/在、傻子/沙子、经/已经、超/潮、有/又、纸/值、哥哥/各个、还/换 | 19 |

**全部 24 条都是「同一个拼音、不同字」**——没有一条是"打不出来"，也没有一条是缺词。

## 二、事实：这些词在词库里吗

| 词 | 在库里的位置（全拼，`type`） |
|---|---|
| 收获 / 收货 | 21.58 / **23.16**（收货第 2） |
| 各个 / 哥哥 | 21.28 / **21.46**（相差 0.18） |
| 傻子 | 首选（句子读成「玩了傻子」，是上下文没把它压下去） |

**结论（事实）：词都在库里，而且大多就在前二。问题不在覆盖率，在同音排序。**

## 三、事实：三个"加宽"实验都没用

| 实验 | 结果（305 句首选命中） |
|---|---|
| `beam` 4（默认） | 281 |
| `beam` 16 / 40 | 283 / 283（+2 句，+0.7%，延迟 6 倍） |
| 语言模型权重 GW 0.5 / 1.0 / 1.5 / 2.5 | 279 / **281** / 278 / 273 |
| 上下文长度 3 / 4 / 5 字 | 281 / 282 / 282（+1 句） |

推断：**搜索宽度、模型权重、上下文长度都已在该引擎的极值附近**，继续加宽是负收益。

## 四、推断：普通输入法赢在哪

1. **个人学习**：他/她、的/得这类，主流输入法靠用户纠正几次就固定；
   Mosto 现在学的是"词"，对「在某个词后面选过哪个同音字」这类上下文偏好覆盖不足。
2. **口语短语统计**：「玩沙子」「收货地址」这种，靠的是大规模聊天语料里的搭配概率；
   万象模型偏书面（48 GB 现代中文语料），口语搭配可能被书面搭配压住。
3. **规则兜底**：的/得、他/她 有确定性规则（得 后面接补语、她 指女性），主流输入法会硬编码一部分；
   Mosto 完全交给语言模型，于是两边都"差一点点"。

## 五、下一步（待会议定，按影响排序）

1. **上下文偏好的学习**：用户在同一前文里改选过某个同音字，下次在该前文后把它提前（不是整词加分）。
   验收：`learn.same` 不降；构造 20 条「同前文同音字」用例，命中率从 0 提到 ≥60%。
2. **的/得 与 他/她 的规则层**：只在前文能判定时生效（动词后 + 补语 → 得；女性称谓 → 她）。
   验收：24 个错例里这两类 5 条修好 ≥4；`sentences.perfect` 不降。
3. **口语搭配的证据**：先把「玩沙子」「收货地址」这类在语料里的实际搭配概率量出来，
   再判断是补一张小搭配表，还是调模型权重——**没有测量之前不补词表**。

## 六、不做的事

- 不加宽 beam、不抬模型权重、不改上下文长度——三项都已实测为负收益或零收益。
- 不靠"补一批词"解决同音排序问题。
