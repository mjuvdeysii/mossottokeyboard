# R15 · 小鹤漏按保持，随机输入不再拖过 40 ms

- 议题：R13 的 CI（run 42531953581，提交 `0185da5`）被 `fuzz.p99.ms` 拦住：小鹤 47.87 ms，门禁 40 ms。键盘测试台因此没有跑。
- 依据：rebase 到 main `9374ccd`（构建 271）。main 已经有两件事，这一版照单保留：
  - `c664fa4` 点首选走 `pendingSelect`，不再 `queue.sync`。`Tools/check_no_sync_tap.py` 继续守这条路径。
  - `985396b` 随机输入跑 3 轮，取最小的 99 分位，门槛仍是 40 ms。
- 本机没有万象句模型。句子准确率门槛会红，要和同一台机器上未改漏按的引擎比，不拿来当这一版的结论。

## 结论

1. 漏按仍从按对的音节（kind 0，且没有被判成按偏）和「多按了一个键」的音节（kind 3）长出去。同一个键位上每一种按对的读法都试。按偏到相邻键的读法不再各猜一遍。
2. 本机无句模型，小鹤门禁三轮取最快：main 9.7 ms，这一版 6.1 ms（单独命令 6.08 ms）。`missing.sentences.top1` 两边都是 9.18。`XMISS=0` 降到 0.00。句子首选、按偏对照组与 main 同一组失败数字。全拼漏按抽样两边都是 47.21；全拼九宫格句子首选在 71 附近有一句的波动（main 这次 70.82，这一版 71.15）。
3. 新的一次解码可以打断正在跑的上一次（6.54 ms → 0.01 ms），结果不写回。打断之后 `nihc` / `nihao` 仍是「你好」。提交、九宫格拼音选择、联想、纠错说明都会先清掉取消标记。
4. 空格走 `decodeNow`，一进来就 `disarmAbandon()`（`abandoned = false` 且 `shouldAbandon = nil`）。联想、九宫格拼音选择、纠错说明同样先清掉取消标记，再干活。点候选仍只读 `pendingSelect` 的缓存，不在主线程等队列。
5. Shift 和地球键不再清掉撤回和滑动清空的恢复。
