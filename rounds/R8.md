## 结论

1. **产品负责人这一轮的「灵活」问题，根因在联想，不在词库、不在 beam。** 模型对 holdout 下一词的 4-gram 覆盖 60.3%，
   引擎 top8 只有 10.6%；5 条「模型知道、引擎永远出不来」的现场例已复现（问题 / 解决 / 帮助 / 邮件 / 火锅）。
2. **开发组找到一处每键都付的账**：偏好文件不存在时，热路径每次 decode 重试数百次 `open()`，20 键解码 2.1×。
   本轮已修（一次性加载 + 上限 + 只在小鹤生成 kind-4 + 删重复 `case`），门禁 38 PASS / 0 FAIL 不变。
3. **设计组的两条判据推翻了 R7 的自我验收**：底栏每格 26.7pt（HIG 的 61%）、颜文字 95 条里 62 条落 10pt。
   R7 写的「高度差 ≤15%」按新公式算不过是自己打自己。本轮按设计组方案改：7 个目的地、21pt 图标、
   选中态改下划线、颜文字按渲染宽度定字号并分组。
4. **必须砍**（产品组，Jobs 的「说不」）：
   - 表情面板再打磨第四轮 —— 冻结；
   - 在 305 句调参集上继续追 `sentences.perfect` —— 该集合已被用于定的/得规则，按铁律不再有验收资格；
   - 微秒级提速（`Path.edges`、`query/encode`）—— 落在 ±10% 噪声里，用户感觉不到；
   - 「联想只记基线」这种形态 —— 基线不是交付。
5. **质检组的否决权从本轮起生效**：只有 RECORD 没有门槛的新功能，一律记为「未验收」。

## 冲突与取舍

- **产品组要「联想做不到就默认关掉」vs 交互组要「先把两字词路径打通」**：两者不矛盾但顺序不同。
  裁决：**先修路径（交互组方案），同一轮内用 ≥60 条验收集复测；达不到 33% 就按产品组意见默认关掉**。
  理由：关掉是退路，不是首选；但必须有明确的关闸判据，否则又会变成「下轮再说」。
- **内容组要「重写三份纪要」vs 时间**：裁决：不重写历史，**新纪要按模板 + 指标台账**，旧的三份标注「数字以本表为准」。
- **设计组要「底栏砍到 7 个」vs 品牌组「Mosto 的脸要露出」**：裁决：脸从底栏移到颜文字分组头（已做），
  底栏用「颜」字；品牌露出仍然每轮一处，不额外加槽位。
